Docs

The dockerpatch server API — what docker install actually talks to, and what submit.html uses to add new packages.

Install one-liner

Patches your local docker CLI to add a new subcommand. Everything else (docker run, docker ps, etc.) passes straight through to the real binary unchanged.

curl -fsSL https://raw.githubusercontent.com/Luishae07/dockerpatch/main/install.sh | bash

Using it

docker install                  # list every available package
docker install <name>           # install one, e.g:
docker install portainer

Every other docker subcommand — run, ps, build, compose, all of it — passes straight through to the real Docker binary, completely unmodified. Only install is new.

How the patch works

install.sh renames your existing docker binary to docker-real, then puts a small wrapper binary in its place named docker. The wrapper checks the first argument: if it's install, it handles that itself (talking to the server below); for literally anything else, it execs straight through to docker-real with all the original arguments untouched. This means it works regardless of your installed Docker version, and a Docker upgrade later won't break it — the wrapper never inspects or depends on Docker's own version.

Uninstalling is the reverse: delete the wrapper, rename docker-real back to docker.

Architecture

piecewhat it does
patch/the wrapper binary (Go) — intercepts install, execs through for everything else
server/serves the catalog and scripts (Go) — this is what docker install actually talks to over the network
packages/the curated install scripts, source of truth alongside server/scripts_bundle.json
ghsearch/Python tool that finds new packages via GitHub code search
index.html / submit.html / findinstalls.html / docs.htmlthis site, served from GitHub Pages

The server is exposed via a Cloudflare quick tunnel — this means its URL is ephemeral and changes on every restart. tunnel-url.txt at the repo root always holds the current one; index.html's package browser and submit.html both fetch it fresh rather than hardcoding a URL, so a tunnel restart never breaks the site itself (though existing local docker install installs may need install.sh re-run if their cached URL goes stale).

Self-hosting the server

You don't need our server at all — server/ is a plain Go program you can run yourself against your own catalog.

cd server
go build -o dockerpatch-server .
./dockerpatch-server          # listens on :8940 by default
env vardefaultpurpose
PORT8940listen port
DOCKERPATCH_CATALOGpackages.jsonpath to the catalog file
DOCKERPATCH_SCRIPTS_BUNDLEscripts_bundle.jsonpath to the bundled script contents

Both files are reloaded from disk on every request — hand-edit them, or run ghsearch against them, and changes show up immediately with zero restart.

Server endpoints

The server backing the catalog — same one docker install and this site's package browser both call.

GET/api/list
Full catalog as JSON. Reloaded from disk on every request — new packages appear without a server restart.
curl $(curl -s https://luishae07.github.io/dockerpatch/tunnel-url.txt)/api/list

[{ "name": "portainer", "description": "Docker management UI", "install_id": "7da65835", "info_url": "/api/info/portainer" }, ...]
GET/api/info/<name>
Returns the relative script URL for one package (plain text), e.g. /scripts/portainer.txt.
curl $(curl -s https://luishae07.github.io/dockerpatch/tunnel-url.txt)/api/info/portainer
→ /scripts/portainer.txt
GET/scripts/<name>.txt
The actual install script — a real docker run command, plain text, ready to execute.
curl $(curl -s https://luishae07.github.io/dockerpatch/tunnel-url.txt)/scripts/portainer.txt
→ #!/usr/bin/env bash
   set -e
   echo "Installing portainer..."
   docker run -d -p 9000:9000 --name portainer ...
POST/api/submit
Adds a new package to the catalog. Used by submit.html after you confirm the extracted command is correct.
{ "name": "my-app", "description": "...", "script": "#!/usr/bin/env bash\nset -e\ndocker run -d ...", "source": "owner/repo" }
fieldnotes
namelowercase letters/digits/hyphens, 2–64 chars, must not already exist
scriptmust contain a real docker run command, max 20,000 chars

Returns 409 if the name is already taken, 400 for invalid input, 200 with {"status":"ok","install_id":"..."} on success.

Install IDs

Each package's install-id is the first 8 bytes of sha256(name), hex-encoded — deterministic, so it never changes across server restarts. Look one up on findinstalls.html.

Catalog sources

Packages come from three places:

sourcenotes
Hand-curateda base set of well-known self-hostable apps (Portainer, Nextcloud, Vaultwarden, Jellyfin, and hundreds more)
ghsearch/a Python tool that runs GitHub code search for "docker run -d -p", extracts the real command from each match, and appends genuinely new ones — deduped by Docker image, not just package name, so the same app found under different repo names doesn't get added twice
submit.htmlyou search for your own repo, it pulls the real docker run command straight out of it, you confirm it's correct, then it's added via POST /api/submit

Because the GitHub-search path is a heuristic scraper rather than a curator, at scale it surfaces some noise alongside genuine finds (base OS images, one-off test repos). This is a known, accepted tradeoff — quantity over cleanup — not something actively filtered further right now.

FAQ

Does this replace Docker itself?
No — it's a thin wrapper around your existing Docker install. Uninstall it any time and your normal docker binary is exactly as it was.
Is the install script safe to run blind?
docker install <name> downloads and runs a real, published docker run command over HTTPS — same trust model as running any install script from the internet. Check /scripts/<name>.txt yourself first if you want to see exactly what it does before running it.
Why does the tunnel URL keep changing?
The server runs behind a free Cloudflare quick tunnel, which issues a new random hostname every time it restarts (no fixed hostname without a paid Cloudflare tunnel). tunnel-url.txt always has the current one — nothing else on this site hardcodes a stale URL.
Can I run my own catalog instead of the shared one?
Yes — see self-hosting above. Point your local docker install wrapper at your own server's tunnel/URL and it works identically.
